# Data flow inventory (WEB-005)

| Data                                                              | Where collected               | Stored where                                                                                                         | Processor          | Purpose                | Retention                      | Deletion                                 |
| ----------------------------------------------------------------- | ----------------------------- | -------------------------------------------------------------------------------------------------------------------- | ------------------ | ---------------------- | ------------------------------ | ---------------------------------------- |
| Contacts, levels, notes                                           | Contact forms, imports        | Browser local storage `yakw_contacts` (session storage fallback)                                                     | none (device only) | The app itself         | Until user clears              | Clear site data or in-app delete         |
| Contacts (backup)                                                 | After optional Google sign-in | Cloud Firestore `user_contacts`, one document per contact (`<uid>_<contactId>`), written only by `lib/cloud-sync.ts` | Google (Firebase)  | Cloud backup           | Until user deletes             | In-app delete; request via GitHub Issues |
| Google account ID, name, email                                    | Sign-in                       | Firebase Authentication; session in browser IndexedDB                                                                | Google             | Sign-in                | Until account removed          | Request via GitHub Issues                |
| UI state: theme, welcome/tutorial progress, sample-cleanup choice | App use                       | Local storage `yakw-theme`, `yakw-welcome-seen`, `yakw-tutorial-progress`, `dc.sample-cleanup-dismissed`             | none               | Remember settings      | Until cleared                  | Clear site data                          |
| Once-per-visit event flag                                         | Contacts page                 | Session storage `dc.first_map`                                                                                       | none               | Count `first_map` once | End of tab session             | Close tab                                |
| IP address, user agent                                            | Every page request            | Firebase Hosting request logs                                                                                        | Google             | Serve the site         | Google defaults                | n/a                                      |
| Usage events (page, CTA)                                          | After analytics consent only  | Google Analytics for Firebase                                                                                        | Google             | Improve the site       | 14 months max (set in console) | Revoke consent; Analytics user deletion  |
| Consent choice                                                    | Consent banner                | Browser local storage `dc.analytics.consent`                                                                         | none               | Remember choice        | Until cleared                  | Clear site data                          |
| Source and CI logs                                                | Git push                      | GitHub                                                                                                               | GitHub             | Build and deploy       | GitHub defaults                | n/a                                      |

Consolidated 2026-11-10: there is one contacts collection, `user_contacts`. The browser store is the source of truth and the cloud copy mirrors it, so deleting a contact, or "Clear all", also removes it from the cloud for a signed-in user. The retired `contacts` collection is read once at sign-in, merged and then emptied (docs/FIREBASE_INTEGRATION.md). For a full deletion request, delete the user's `user_contacts` documents (filter by `userId`) and their Firebase Authentication record; check `contacts` too until every user has signed in once.

Privacy policy audit against this table: done 2026-11-10 (`src/pages/PrivacyPage.tsx`). Legal review still required (QA.md section 5).

Firestore rules (`firestore.rules`) restrict reads/writes to the owning signed-in user. Deployed rules must be verified after each change: `firebase deploy --only firestore:rules` then run the emulator tests in SECURITY.md.
